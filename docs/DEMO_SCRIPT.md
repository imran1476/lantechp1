# ৩ মিনিটের ডেমো ভিডিও — স্ক্রিপ্ট

আগে থেকে ঠিক করে রাখুন: ডেটা-ফোল্ডার মুছে নতুন করে সার্ভার চালু (`rm -rf data && npm run dev`), দুটো ব্রাউজার প্রোফাইল (একটায় `operator`, অন্যটায় `reviewer`)।
`GEMINI_API_KEY` থাকলে `samples/khatian_06.png` আসল OCR-এ চলবে। না থাকলে আপলোড ডেমো ডেটা দেবে (স্ক্রিনে সতর্কতা আসবে) — তখন সিড করা `১২৬০` নম্বর রেকর্ড দিয়ে "ভুল ধরা" অংশ দেখান এবং ভিডিওতে সৎভাবে বলুন যে OCR ধাপটি এখানে ডেমো।

| সময় | কী দেখাবেন | কী বলবেন |
|---|---|---|
| ০:০০–০:২০ | লগইন পেজ (বাংলা), তারপর `operator` দিয়ে ঢোকা | পুরোনো খতিয়ান ছবি হয়ে থাকলে তথ্য খোঁজা-মেলানো-যাচাই কঠিন; আমরা যাচাইকৃত অনুসন্ধানযোগ্য ডেটা বানাই। লগইন ও রোল আছে। |
| ০:২০–০:৫০ | "নথি আপলোড" → `khatian_06.png` (কাত/নয়েজ চালু) → ফলের ফিল্ড | ছবি পরিষ্কার হলো, বাংলা OCR থেকে মালিক, অংশ, দাগ ও পরিমাণ আলাদা হলো। |
| ০:৫০–১:২০ | পর্যালোচনা পেজ: লাল "দাগের যোগফল ≠ মোট জমি" | ছাপা নথিতে মোট জমি ভুল; OCR ঠিকঠাক পড়লেও সিস্টেম নিজেই ভুল ধরল। ভুল থাকলে অনুমোদন বোতাম বন্ধ। |
| ১:২০–১:৫০ | "সংশোধন করুন" → দাগ-তালিকা/মোট ঠিক → সবুজ | কর্মকর্তা ভুল শুধরালেন; পরিবর্তন লগে গেল। |
| ১:৫০–২:২০ | `reviewer` দিয়ে অনুমোদন → আর্কাইভে সার্চ: `মোহাম্মদ কাল্পনিক` → "মোঃ কাল্পনিক…" নামের রেকর্ড | অনুমোদিত রেকর্ডে সার্ভার আবার যাচাই করে সিল করল; বাংলা নামের বানান-বৈচিত্র্যেও খুঁজে পায়। |
| ২:২০–২:৪০ | রেকর্ড বিস্তারিত → ইতিহাস → "অখণ্ডতা যাচাই" | প্রতিটি কাজ SHA-256 হ্যাশ-চেইনে; কিছু বদলালে ধরা পড়ে। |
| ২:৪০–৩:০০ | জরিপ-সংযোগ ট্যাব, তারপর বাস্তবায়নের তিন ধাপ | একই দাগের CS-SA-RS-BS জোড়া; পাইলট → জেলা → দেশ, ই-নামজারি সংযোগ ভবিষ্যতে। সীমাবদ্ধতাও খোলাখুলি বলুন। |

টিপস: একটা ইচ্ছাকৃত ভুল (khatian_06 বা khatian_08) দিয়েই "ভুল ধরা" দেখান; নির্ভুলতার কোনো সংখ্যা মাপা ছাড়া বলবেন না।
